# 一、为什么 TCP 需要三次握手？

因为 TCP 是一个 **可靠传输协议**，它必须保证：

1. **双方都能发送数据**

2. **双方都能接收数据**

3. **双方都知道对方的初始序列号**

三次握手就是为了让双方同步这些状态。

# 三、为什么不是两次握手？必须是三次

**原因 1：确保双方都能“发送 & 接收”**

- 只靠 SYN，无法保证服务器的 SYN 能被客户端收到

- 两次握手无法确认 **双方都具备收发能力**

**原因 2：防止“历史连接”误触发**

如果之前断开的连接残留 SYN 包重新到达服务器（网络延迟），\
服务器可能会误以为客户端又要连接，造成 **脏连接（Half-Open Connection）**。

三次握手中的 ACK 可以防止这个问题。

**原因 3：双方序列号必须互相确认**

TCP 传输要可靠，就必须确认双方的初始序列号；\
两次握手无法让双方都确认序列号。

# 四、三次握手的关键点总结

|步骤|作用|内容|
|---|---|---|
|第一次握手|客户端告诉服务器要建立连接|SYN，Seq=x|
|第二次握手|服务器接受连接并告诉客户端自己的序列号|SYN+ACK，Seq=y，Ack=x+1|
|第三次握手|客户端确认服务器的序列号|ACK，Ack=y+1|

最终双方均获得：

- 对方的初始序列号

- 对方的收发能力状态

- 完整建立的会话通道\
